Dynamic Vapor Flow: Fix Strategy
Problem Summary
The energy-based vapor flow model (vapor_flow_model="energy" ) is theoretically correct but numerically
unstable due to:
1. Zero temperature target (dT_target = 0) forces the model to increase vapor flow when ANY energy
enters
2. Very slow relaxation (60 seconds) allows errors to accumulate before correction
3. Large clamp limits (5× nominal) permit huge deviations before intervention
4. Feed thermal shock at stage 12 creates massive energy imbalance
Root Cause Analysis
The Energy Balance Equation (Line 782-789)
With dT_target = 0 → dE_target = 0, this becomes:
Problem: At the feed stage (12):
Feed adds 7,143 lbmol/h × hF ≈ huge energy input
To maintain dT/dt = 0, must generate MORE vapor
But generating vapor REQUIRES heat, which INCREASES temperature
This creates positive feedback
Why It Grows Without Bound
t=0: ChemSep steady state, V_out = 7,345 lbmol/h at stage 12 t=1: Feed energy imbalance → energy wants
V_out = 15,000 t=1: Relaxation (α=0.017) → V_out = 7,345 + 0.017×(15,000-7,345) = 7,475 t=2: Higher
V_out generates vapor → T increases slightly → enthalpies change t=2: Energy balance recalculates with new

Solution 5: Enable Hydraulic Pressure Model (Long-term)
Why It Helps
Hydraulic pressure provides negative feedback:
1. Higher vapor flow → higher pressure drop
2. Higher ΔP → lower upstream pressure
3. Lower P → higher latent heat required
4. Higher latent heat → lower vapor flow (for same energy)
This natural throttling prevents runaway.
Implementation
Fix the reboiler pressure bug first (line 1722):
python
if feed_stage0 == i:
    # Energy required to bring feed to tray conditions
    # Reference to tray liquid enthalpy (already in denominator)
    q_feed = Ft_L * (hF_L - hL_out) + Ft_V * (hF_V - hL_out)
    
    # This way, if feed is at tray temperature, q_feed ≈ 0
    # If feed is cold, q_feed < 0 (removes energy, reduces vapor)
    # If feed is hot, q_feed > 0 (adds energy, increases vapor)
