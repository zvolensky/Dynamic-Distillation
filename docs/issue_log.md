- `DD-032` (`Reframed`; 2026-06-03 pragmatic path): After systematic exploration through June 2, the initialization problem has been definitively reframed. The deficiency is not a collection of fixable local problems; it is a **structural under-constraint of a stiff DAE system** that cannot be solved by sequential profile tweaking, local residual fits, or boundary-only heuristics. The reflux-drum composition couples bidirectionally to condenser duty, top-vapor state, stage-2 composition/temperature, feed-stage transport, and the entire vapor-flow/pressure/energy network. Attempting to solve it locally (PF closure, boundary composition, terminal-layer fits) systematically transfers the residual to untargeted regions; solving it globally with independent tray-by-tray variables worsens behavior because the variable space is too blunt. This is precisely the under-constraint problem that Pantelides (1988) proved requires **simultaneous solution of all derivatives and algebraic constraints** across the entire system. **Recommended pragmatic path**: Abandon the pursuit of a static Excel-based golden seed (which is mathematically impossible for this model). Instead, use the continuous-operating checkpoint at t=60s (score=1.43, `max_rel_state_rate≈0.00463 1/s`, `max_temp_rate≈0.352 F/s`) as a **quasi-settled operational baseline** for validation work <100s horizon. Implement binary checkpoint serialization (pickle/HDF5) that captures full state, controller memory, thermo cache, and hydraulic context—not Excel restart which lost this state and caused a score spike to 135 on reload. This allows development, disturbance validation, and controller tuning to proceed while deferring the true Pantelides solver decision. If a future `tools/solve_reflux_drum_composition.py` test improves t=120s behavior materially (e.g., score <5), pursue coupled-boundary initialization; otherwise, accept that this explicit-vapor/energy topology's natural state is continuous operation under control, not static initialization. See `docs/dynamic_column_initialization_strategy.md` § "Pragmatic Path: Continuous-Operating Checkpoint Initialization" for implementation details and staged learning plan.
